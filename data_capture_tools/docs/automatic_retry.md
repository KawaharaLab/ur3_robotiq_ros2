# 自動収集中の一時異常からの自動再試行

ac/arの収集ループに、停止・記録終了後の回復待ちを追加しました。完了済み試行の条件・判定・保存内容を変更する機能ではないため、この変更だけを理由に既存データを取り直す必要はありません。既存の品質チェックで問題がある試行の扱いは別途判断してください。

## 流れ

1. 従来どおり異常を検出し、動作の停止を確認します。
2. 中断した実行はABORTとして残し、bagを閉じて整合性を検証します。検証できた完了済み試行は維持します。
3. 再試行対象の異常だけ、動作を送らずに最大30秒待機します。正常な画像・力覚・状態の受信等が連続2秒確認できた場合に再試行します。待機中もEnterで手動中断できます。
4. 保存済みinitが有効なら再利用し、未完了試行を準備の開放・ゼロ点取得からやり直します。試行途中からつなぎ合わせません。停止中は対象物に接触したまま待機する場合があります。
5. 同一試行で最大3回、1回のac/ar呼出しで合計20回まで再試行します。回復待ちがタイムアウトした場合や上限に達した場合は、通常のar待ちへ戻ります。手動arは新しい再試行予算を開始します。

再試行は対象試行への接触履歴・経過時間を増やす可能性があります。失敗した実行と待機・再試行履歴を進捗JSONに残し、必要なら学習前に区別できます。再試行待ちの全時間が画像bagに記録されるわけではありません。

## 対象

- GelSight画像の未受信・受信途絶・デコード失敗
- 画像または力覚のHeaderが古い等の鮮度異常
- 力覚の受信途絶
- 追加時刻記録の一時的な未受信
- bag開始時に必要な購読を確認できない場合

これらでも、停止を確認できない、bag整合性を検証できない、initの途中で失敗した、別の重大な異常も発生している場合には自動再試行しません。接続が戻らない場合に、動作だけを繰り返すことはありません。

**自動再試行しないもの：** 力上限、非有限の力値、手動中断、終了操作、センサのストリーム再起動検出、ロボット・グリッパ異常、位置・ドライバ変更、停止確認失敗、保存・bag検証失敗。力上限や鮮度の閾値は変更していません。センサを再起動した場合は従来の手動arを使います。

## 設定

設定なしでも上記の既定値で有効です。変更する場合、data_capture.yamlの`automatic_collection`の内側ではなく、同じ階層に追加します。再試行設定は現在のYAMLから読み、収集条件として固定された既存計画の深さ・速度等は変更しません。既存の進捗JSONでarする場合にも適用されます。

```yaml
automatic_retry:
  enabled: true
  max_per_trial: 3
  max_per_run: 20
  wait_timeout_s: 30.0
  stable_s: 2.0
  minimum_wait_s: 2.0
```

無効化する場合は`enabled: false`です。待機時間は壁時計ではなく単調増加時計で計測します。

## 記録

進捗JSONの`automatic_retries`に対象試行・中断理由・試行内/実行内の回数・適用設定・待機開始/終了のROS時刻・回復または手動対応が必要になった結果を残します。各trialの`attempts`には従来どおり失敗した実行も残ります。再試行上限に達した場合は`automatic_retry_stop`にも記録します。新しいac/ar呼出しで過去の履歴を削除しません。

## 反映と短い確認

研究用リポジトリへ最新版を反映後、ワークスペースで以下を実行します。

```bash
cd /home/tsumura/my_robotiq_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select data_capture_tools
source install/setup.bash
```

データ収集ノードだけ終了・再起動して、既存ジョブはarで再開できます。終了しても動作が続いている場合や停止を確認できない場合は再開しないでください。ドライバ類を変更・再起動する必要はありません。

最初は1位置・少数試行で確認してください。手動Enterでは待機・自動再試行せず通常の中断になることを確認します。画像/力覚等の一時異常で自動回復を待ち、復帰しない場合はタイムアウト後にar待ちになることを確認します。実機での自動再試行はこれから検証する必要があります。
