# 基板・配線交換前後の力応答の比較

`utils/diagnostics/compare_force_hardware.py`は、旧・新のextract_all展開結果から同じ条件の完了試行だけを選び、左右Fyの波形と試行単位の指標を比較します。元bag・元CSV・JPEGは変更しません。画像展開・再圧縮も行いません。Pythonのnumpyとmatplotlibが必要で、ROSノードの起動やcolcon buildは不要です。

## 今回の実行例

```bash
cd /home/tsumura/my_robotiq_ws
/usr/bin/python3 src/ur3_robotiq_ros2/utils/diagnostics/compare_force_hardware.py \
  --old-export /mnt/nvme1/tsumura/masters_thesis/exports/object46 \
  --old-job 20261111_185936_5f3edfd4 \
  --new-export /mnt/nvme1/tsumura/masters_thesis/hardware_validation/board_cable_20261113/exports/object46 \
  --new-job 20261113_153717_39022b4e \
  --out /mnt/nvme1/tsumura/masters_thesis/hardware_validation/board_cable_20261113/comparison_object46_run1
```

入力は各エクスポートのルートかセッションフォルダです。ルート直下・一段下・二段下のmanifestを探します。同じジョブを複数回展開したフォルダが混在して重複する場合は、片方のエクスポートルートへ絞ってください。曖昧な入力を自動で混ぜません。出力先が既にあれば拒否するので、新しい名前を指定してください。

## 対応条件

位置、動作種別、深さ、速度、保持時間、揉み回数、準備速度、開放速度、開放余裕、variantを一致させます。数値の4と4.0は同じとします。試行番号やrepeat番号は対応条件にせず、各構成の反復をまとめて比較します。

今回の旧184試行・新30試行では、設定が一致していれば10条件群・旧20試行・新30試行になる想定です。採用した試行・一致しなかった条件はreport.jsonに残します。initの幅は一致条件にはしません。試行のinit_idと保存済み参照が一致したときだけ、幅をtrial_metrics.csvへ記載します。不明な幅を推測しません。

## 最初に見る出力

- `plots/`：条件ごとのPNG。位置・動作・深さをファイル名に含みます。赤=旧、青=新、左右は別列です。
  - 上段：記録済みtareを引いた生波形。全振幅を表示します。
  - 中段：Hampel法の候補点を表示から除いた波形。候補点を補間せず、時刻の空きも線でつなぎません。
  - 下段：実際の動作イベントで特定した各保持区間の終盤の中央値。各試行の点であり、各サンプルを独立な反復として扱いません。
- `comparison_index.csv`：対応条件・PNG・新旧の試行数。
- `summary.txt`：対応試行数・候補サンプル数・保持イベントがない試行数。
- `report.json`：入力ハッシュ、計画設定、採用試行、処理条件、制約事項。

追加出力：

|ファイル|内容|
|---|---|
|trial_metrics.csv|試行×左右の候補割合、時刻の空き、生ピーク、候補除外後の絶対値95百分位、tare、対応が確認できたinit幅など|
|hold_metrics.csv|試行×左右×保持区間の初期/終盤中央値、緩和率、利用できたサンプルの割合|
|group_differences.csv|各条件・左右・保持区間について、新旧各反復の中央値・範囲と差|
|spike_candidates.csv|候補点の時刻・値・局所中央値・判定閾値。補間済みデータではない|

`new_minus_old`は符号付きの差です。旧−6 N・新−8 Nなら−2 Nとなります。`absolute_force_change_n`なら力の絶対値の増分+2 Nです。`relaxation_fraction`は、保持初期から終盤への力の絶対値の減少率です。初期力が0.2 N未満なら計算しません。

## 処理の定義と限界

生波形は記録済みtareだけを引きます。最大値等による振幅正規化、力の立ち上がりに合わせた時間移動、時間伸縮は行いません。横軸は各TrialEvent STARTからのHeader時刻です。指令から接触までの違いも残ります。

Hampel候補の既定値は中心21サンプル窓、局所中央値から6×1.4826×MADを超える点です。判定幅の下限は2.5 Nです。約1000 Hzで約21 msに相当しますが、時間窓ではなくサンプル窓です。5 ms超の時刻の空きや時刻逆転をまたいで適用せず、端の10点と短い区間は判定しません。元データは変更せず、候補は可視化・指標から一時的に除外するだけです。以前のプロットにある隣接3点の孤立スパイク判定とは異なり、候補数を直接比較できません。

候補はノイズの確定ラベルではありません。実際の鋭い応答を候補にする可能性もあり、長く続く異常は残る可能性があります。生波形と必ず比較してください。`retained_over_30n_samples`は除外後にも30 N超が残るかの確認用で、それ自体を追加の除外規則にはしません。これは学習用の前処理を確定するコードではありません。

保持区間は`robot_action_event.csv`のauto_dwell_start/endを使います。初期は開始直後の最大20 ms（または区間長の10%）を避けた25%幅、終盤は最後の25%幅で中央値を計算します。推定サンプル数に対して80%以上、かつ10点以上利用できる窓だけ計算します。候補点・非有限値を除き、ギャップを補間して値を作りません。揉みは各周期の深い/浅い保持を別々に集計します。

旧エクスポートに動作イベントがない場合、波形から保持開始を推定しません。生波形と候補の比較は生成しますが、旧の保持・緩和指標と新旧差は空欄になります。report.jsonのtrials_without_hold_eventsで確認してください。全イベントが揃わない試行も別に報告します。必要なら元bagから補助CSVを追加するか、現行extract_allで再展開します。新しい実機収集が必要という意味ではありません。

完全な同等性・校正精度・交換の因果効果を自動で合否判定する処理ではありません。取付、init、試料履歴、日差等は依然として混在します。力覚以外の接触状態は既存GelSightプロットで確認してください。中断回数は完了エクスポートだけでは比較できないため、進捗JSONで別途評価します。比較前に厳密チェックの指摘も参照してください。

## 結果の共有

まずsummary.txt、report.json、trial_metrics.csv、group_differences.csvを共有してください。PNGは気になる条件を数枚で構いません。これにより「通常の力応答は揃ってノイズだけ減ったか」「保持指標の比較に旧イベントが必要か」を判断できます。
